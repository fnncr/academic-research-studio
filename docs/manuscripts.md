# P2: ручная рукопись, план и история версий

Рукопись создаётся с нуля без модели и внешних API. В разделе «Проекты» выберите проект и нажмите «Открыть рукопись». Добавьте заголовки для плана, абзацы, цитаты, списки, таблицы и заготовки ссылок. Кнопки «Выше»/«Ниже» меняют порядок блоков, сохраняя их ID. Удаление и редактирование можно отменить; в памяти вкладки хранятся последние 30 изменений. Заголовки уровней 1–6 формируют навигационный план.

«Сохранить версию рукописи» создаёт неизменяемый снимок в PostgreSQL. История позволяет сравнить любую сохранённую версию с текущим черновиком и загрузить её для восстановления. Восстановление завершается **отдельным сохранением новой версии**; старые версии не удаляются. Если после загрузки старой версии изменить текст, сохранение считается обычной редакцией, а не точным восстановлением.

## Решение о редакторе

Для P2 выбран небольшой редактор блоков на существующих React/TypeScript и нативных полях ввода. Новых зависимостей нет; React — MIT, TypeScript — Apache-2.0. ProseMirror остаётся кандидатом для будущего inline-редактирования: в этой поставке не требуется новый редакторский runtime, плагины и синхронизация HTML. Цена решения — отсутствие WYSIWYG и форматирования отдельных слов. Полужирное/курсивное оформление задаётся всему абзацу, цитата и заготовка ссылки являются отдельными блоками. Это ограниченный структурный редактор, не полная копия Word.

UI работает с тем же версионированным деревом, которое валидирует backend. Дерево не содержит HTML, исполняемого кода и автоматически подтверждённых источников. Текст отображается React с экранированием. Выбор другой библиотеки в будущем не должен переписывать сохранённые снимки: потребуется конвертер и новая версия схемы.

## Схема документа 1

Корень: `{schema_version: "1", blocks: [...]}`. Порядок массивов значим. Каждый блок, пункт списка, строка и ячейка таблицы имеет UUID, уникальный во всём снимке. Идентификаторы сохраняются при правке/перемещении/восстановлении, новые элементы получают новые UUID. Это основа будущих ссылок и замечаний; вычисление текстовых диапазонов UTF-16 относится к P4/P7 и здесь не реализовано.

| type | Поля кроме id/type |
| --- | --- |
| paragraph | text; marks: массив `bold`/`italic`; origin: `manual`/`docx_plain_text`/`pdf_plain_text`; page: номер страницы PDF или null |
| heading | text; level: 1–6 |
| quote | text; принадлежность источнику пока не подтверждается |
| list | ordered: boolean; items: непустой массив paragraph |
| table | rows: массив `{id, cells: [{id, text}]}`; одинаковое число ячеек в каждой строке |
| citation_placeholder | label: источник или задача поиска; locator: страница/раздел; связи с источником ещё нет |

Заготовка ссылки — **не проверенная ссылка**. В P4 появится связь с конкретной версией источника и доказательством. Никакие DOI, имена авторов или сведения о публикации редактор не придумывает.

Лимиты: 1000 верхних блоков, 2000 узлов всего, 250 000 Unicode code points в текстовых полях, 20 000 на одно поле текста, 500 на label/locator. Список: до 200 пунктов, таблица: до 100 × 20 ячеек. Пустая рукопись разрешена. Неизвестные поля/типы/версии, повтор ID, непрямоугольная таблица, NUL и непарные суррогаты отклоняются. HTTP-запрос ограничен 2 МиБ и 15 секундами, в том числе без Content-Length. Браузерные maxLength считают UTF-16 и для некоторых символов строже серверного ограничения.

## Версии, конфликты, восстановление

Миграция `0002_manuscripts` добавляет одну таблицу, не меняя проектов и требований. Версия хранит project_id, последовательный number, parent_id, document JSONB, content_hash, request_id, request_hash, restored_from_id и время. SHA-256 вычисляется по JSON с сортировкой ключей, без ASCII-экранирования и пробелов. Хеш подтверждает неизменность, а не научную достоверность текста.

Сохранение блокирует строку проекта и проверяет base_revision_id. Для первого сохранения база — null: из двух параллельных первых сохранений только одно проходит. Чужая/устаревшая база даёт `409 revision_conflict`; чтение версии другого проекта даёт 404. Неизменяемость сохранённых строк обеспечивается также PostgreSQL-триггером для UPDATE/DELETE. Сетевой многопользовательской авторизации пока нет; режим локальный, для одного владельца.

При конфликте UI сохраняет черновик и запрещает повторное сохранение до сравнения. «Проверить актуальную версию» показывает актуальный текст рядом с черновиком. Пользователь переносит нужные изменения вручную и явно выбирает новую базу либо берёт актуальный текст. Автоматического объединения нет. Даже после сравнения новая конкурирующая запись снова приведёт к 409.

Повтор точно того же request_id и тела возвращает первоначальную версию, даже если позже появились новые. Другое тело с тем же ключом даёт `409 request_conflict`. UI повторяет прежний ключ после неопределённого сетевого исхода, пока тело не менялось. При изменении черновика используется новый ключ; optimistic locking защищает от перезаписи уже сохранённого ответа. История использует курсор `before` по номеру, поэтому новые сохранения не сдвигают страницы уже запрошенной истории.

Для точного восстановления клиент передаёт старый document и restored_from_id. Сервер проверяет принадлежность проекту и полное совпадение снимка; расхождение — `422 restore_mismatch`. Родителем остаётся актуальная версия, а восстановленный источник записывается отдельно.

## API

Все маршруты ниже имеют префикс `/api/projects/{project_id}/manuscript`:

| Метод и путь | Ответ / назначение |
| --- | --- |
| GET (без суффикса) | Последняя версия с document или null для ещё не созданной рукописи |
| GET /revisions?limit=20&before=21 | История по убыванию номера, без тяжёлого document; limit 1–100 |
| GET /revisions/{revision_id} | Неизменяемая версия с document |
| POST /revisions | 201: новая версия или результат точного повторного запроса |

Тело POST: `{base_revision_id: UUID|null, request_id: UUID, document: {...}, restored_from_id: UUID|null}`. Content-Type — application/json. При недоступной/неприменённой БД — безопасный 503. Ошибки структуры не возвращают содержимое рукописи, SQL или параметры подключения. API отдаёт Cache-Control: no-store. Сравнение выполняется в UI по устойчивым ID блоков; показывает до/после текста и структуры, форматирование, вставку, удаление и смену позиции. Это сравнение блоков, не посимвольный diff и не Word Track Changes.

## Импорт и сохранность

Импорт использует существующий `/api/documents/extract` с прежними лимитами. В конец черновика добавляются исходные текстовые chunks, без догадок о заголовках, ячейках, сносках и цитировании. Страницы PDF и признак plain-text импорта сохраняются. До импорта и после него видна информация о потерянной структуре; исходная разметка не считается известной даже при последующей ручной установке bold/italic. P7 должен учитывать эту неполноту при оценке исходного форматирования.

Оригинал DOCX/PDF не сохраняется; при сохранении версии сохраняется добавленный текст. Если результат превышает лимиты рукописи, добавление отклоняется целиком, исходный черновик остаётся. Для очень больших chunks используйте самостоятельное извлечение и перенос подходящих частей вручную. OCR и lossless DOCX round-trip не реализованы.

Черновик хранится только в памяти вкладки. При переходе в другой проект или закрытии страницы UI предупреждает о несохранённых изменениях/незавершённом запросе; это не защита от аварийного завершения браузера. Переключение между «Проекты» и «Извлечение текста» оставляет открытый редактор смонтированным. Сохраняйте версию перед закрытием. LocalStorage и внешние сервисы для пользовательского текста не используются.

Настройте PostgreSQL по [P1a](projects.md), выполните `alembic upgrade head`. Логический backup БД включает всю историю рукописей. Downgrade до P1 удаляет рукописи: применять только на одноразовой БД или после проверенного резервирования. Для отката приложения предпочтительно оставить аддитивную таблицу. Автоматические backup и удаление проекта требуют отдельной реализации P1/P10 с учётом триггера неизменяемости.

## Проверки

Полный pytest с TEST_DATABASE_URL проверяет Unicode/таблицы после перезапуска, конкурентное первое и последующее сохранение, повтор после потерянного ответа, курсорную историю, восстановление, изоляцию project IDs, rollback при ошибке INSERT, сохранность P1 при миграции и запрет UPDATE/DELETE. Валидация проверяет неизвестные структуры, вложенные повторные ID и лимиты. Старые тесты извлечения и P0 сохранены.

Frontend-тесты покрывают ручной сценарий, план, таблицы/ссылки, устойчивые ID, undo/redo, сравнение конфликта, восстановление, повтор запроса, импорт и предупреждение при выходе. TypeScript/Vite проверяют сборку. Реестр всех 34 критериев остаётся неизменным; их автоматические проверки появятся в P7/P8.
