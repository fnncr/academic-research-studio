# P3: первая поставка научной библиотеки

Работают ручные карточки и версии библиографических данных, дубликаты DOI/ISBN, поиск Crossref/OpenAlex, сверка DOI по каталогам, журнал результатов/ошибок и сравнение противоречащих метаданных. Это сценарий работы с **метаданными**, не проверка полного текста или научной достоверности.

В проекте нажмите «Открыть библиотеку источников». Создайте карточку либо введите отдельный запрос, выберите каталоги и разрешите передачу. Рукопись и требования не включаются в запрос. Результаты не сохраняются в библиотеку автоматически: перенесите выбранную запись в форму и сохраните карточку. Типы: статья, монография/книга, диссертация, отчёт/официальное исследование, данные/статистика, другое. Язык хранится отдельно. Материалы университетов и официальная статистика, отсутствующие в каталогах, добавляются вручную. Покрытие языков/дисциплин не гарантируется; порядок выдачи не означает научную значимость.

## Что подтверждается

- Все карточки имеют `verification: unverified`. `manual` и `catalog_metadata` обозначают происхождение, не доказательство содержания.
- DOI нормализуется и проверяется синтаксически. Отдельная разрешённая сверка фиксирует source_version_id и сравнивает метаданные с Crossref/OpenAlex. `metadata_match` — совпадение заполненных полей, `conflict` — различия, `insufficient_metadata` — недостаточно названия/авторов/года. Совпадение не подтверждает утверждений исследования.
- ISBN проверяется по контрольной сумме. ISBN-10 переводится в ISBN-13 для дедупликации. Существование книги в каталоге издателя/библиотеки пока не проверяется.
- HTTP(S) URL без credentials сохраняется, но **не запрашивается**. Доступность страницы остаётся непроверенной. Универсального URL checker нет.
- 401/403, 429, таймаут, сетевой отказ, редирект, слишком большой/неподдерживаемый ответ — отдельные состояния недоступности. 404/пустая выдача не доказывает отсутствия публикации.

## Версии и конфликты

`Source` принадлежит проекту. Неизменяемый `SourceVersion` содержит metadata, provenance, номер и время; UPDATE/DELETE запрещены PostgreSQL-триггером. P4 должен ссылаться на source_version_id, а не latest_version. Чтение версии проверяет принадлежность проекту. Evidence, цитаты и полные тексты будут отдельными сущностями.

Метаданные: title, authors (коллективный автор допустим строкой), year/null, kind, language/und, container, publisher, doi, isbn, url. Схема отвергает неизвестные поля, повреждённый Unicode, неправильные идентификаторы и небезопасные схемы URL. Запросы ограничены 128 КиБ / 15 секундами. Ошибки не возвращают текст карточки или SQL.

`SourceIdentifier` хранит принадлежность текущего DOI/ISBN источнику внутри проекта. Сохранение под блокировкой проекта атомарно проверяет уникальность, создаёт версию и обновляет идентификаторы. Исправленный старый идентификатор сохраняется в истории, но освобождается для правильной карточки. По названиям/фамилиям автоматического объединения нет.

Дубликат даёт 409 с существующими карточками и различиями. UI сохраняет предлагаемую форму, показывает сравнение и позволяет явно исправить существующую карточку. Новая запись требует base_version_id; конкурирующая правка даёт 409 без перезаписи формы. request_id + хеш тела делают повторы идемпотентными, включая потерю ответа; другой текст с тем же ключом отклоняется.

## Воспроизводимый журнал

`SearchRun` сохраняется **до сети**: запрос, провайдеры, лимит, годы, согласие, целевая версия DOI-сверки, время. После вызовов сохраняются нормализованные snapshots hits, позиции, версия адаптера, время попытки, ошибки и число отклонённых записей. Совпадающие DOI/ISBN внутри выдачи связываются, расхождения видны. Полные ответы/абстракты/тексты/ключи не сохраняются. Воспроизводим сохранённый снимок, а не будущий ответ изменяющегося каталога.

Происхождение импорта проверяется сервером: search_run_id принадлежит проекту, hit_id существует, metadata совпадает со снимком. Ручное изменение поля снимает утверждение о точном результате каталога; исходный снимок остаётся в журнале.

После аварии run может остаться `pending`: завершённого результата нет, это не успех. Повтор того же request_id не делает ещё один внешний вызов. Обновите журнал; после прерванного процесса явно запустите новый поиск. Очередь, lease и автоматическое возобновление относятся к P6. Блокировка проекта освобождается перед сетью, лимиты сети не удерживают её.

## Сеть, условия и эксплуатационная проверка

Разрешены только жёстко заданные `https://api.crossref.org/works` и `https://api.openalex.org/works`. DOI URL-экранируется в пути, запрос/фильтры передаются как параметры. Пользователь не задаёт адрес назначения; ссылки из ответов не обходятся. TLS включён, системные proxy/CA сохраняются. **Все редиректы запрещены**, включая loopback, private IP и metadata endpoints. Это ограниченная защита от SSRF без небезопасного универсального fetcher и проверки DNS «до запроса».

На провайдера: общий deadline 12 секунд, connect 3 секунды, HTTP timeout 5 секунд, ответ до 1 МиБ. Запрашивается identity encoding, неожиданное сжатие отклоняется. До двух поисков одновременно на процесс API, каждый до двух провайдеров; 1–10 результатов/провайдер (UI: 5). Нет бесконечных retry, обхода выдачи или массового скачивания. Перед публичным доступом нужны авторизация и внешние rate limits; текущий режим локальный.

Окружение:

- `OPENALEX_API_KEY` — ключ, если требуется текущей политикой/тарифом. Не сохраняется в БД/коде/ответах. Не включать отладочное логирование HTTP URL: API передаёт ключ в query.
- `SOURCE_API_CONTACT` — реальный email для polite pool, если пользователь решил его передавать каталогам. Выдуманный контакт не используется.
- HTTPS egress: `api.crossref.org`, `api.openalex.org`. Доступ меняется настройками среды, не редактированием локального network-policy.json.

3 ноября 2026 года обе живые попытки в среде разработки завершились ProxyError: домены не разрешены действующей политикой. **Успешный live-поиск и актуальные квоты не подтверждены.** Контрактные тесты используют синтетические HTTP-ответы. Для эксплуатационной приёмки разрешить домены, проверить текущие условия/ключи и выполнить ограниченный живой поиск без пользовательских документов.

Прочитанные первичные материалы: [Crossref REST API](https://github.com/CrossRef/rest-api-doc) (помечен deprecated; актуальная документация — https://api.crossref.org/), [OpenAlex documentation](https://github.com/ourresearch/openalex-docs) и [search works](https://github.com/ourresearch/openalex-docs/blob/main/api-entities/works/search-works.md) (репозиторий архивирован; актуальные условия — https://docs.openalex.org/). Архивные документы допускают кеширование библиографических метаданных Crossref и описывают OpenAlex metadata как CC0. Это не разрешение на массовую загрузку статей или обучение на полных текстах; актуальные условия ещё требуют проверки. BAWE/MICUSP рассматриваются отдельно в [корпусном модуле](research-quality.md).

Новых зависимостей нет: httpx уже закреплён в requirements.txt (BSD-3-Clause), используются существующие SQLAlchemy/Pydantic/React.

## API и миграции

Префикс `/api/projects/{project_id}`:

| Маршрут | Назначение |
| --- | --- |
| GET /sources?limit=20&offset=0 | Карточки с latest_version |
| POST /sources | `{request_id, metadata, base_version_id:null, origin:null|{search_run_id,hit_id}}` |
| GET /sources/{id} | Одна карточка |
| POST /sources/{id}/versions | Те же поля с актуальной base_version_id |
| GET /sources/{id}/versions?before=N&limit=20 | История по номеру |
| GET /sources/{id}/versions/{version_id} | Зафиксированная версия |
| GET /search-runs?limit=10&offset=0 | Журнал с результатами/ошибками |
| POST /search-runs | `{request_id, query, providers, limit, year_from, year_to, mode:"search"|"doi", source_version_id:null|UUID, consent:true}` |

Search mode требует source_version_id=null; DOI mode — совпадающий DOI выбранной версии и отсутствие фильтров лет. Фильтры относятся к году публикации по данным провайдера. Перевод, оценка утверждений и сравнение научных позиций относятся к P4/P6/P8.

`alembic upgrade head` добавляет `0003_sources`, сохраняя P1/P2. Backup PostgreSQL включает всю библиотеку/журнал. Downgrade до 0002 удаляет эти данные: только одноразовая БД или проверенный backup; откат приложения может оставить аддитивные таблицы. Автоматическое резервирование/удаление проектов ещё не реализованы.

Тесты: реальные PostgreSQL-схемы для атомарности, повторов, конкуренции, миграций, неизменяемости и принадлежности; MockTransport для API, timeout/403/404/429/редиректов/лимитов/невалидных ответов/ключей; UI для карточки, дубликата, конфликта, происхождения выдачи, согласия и сетевого отказа. Синтетические DOI/ISBN не заявляются существующими публикациями.
