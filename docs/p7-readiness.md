4 ноября 2026 года; основание main `99ef8b9`, [аудит](validation/p6-independent-audit.md).
**Можно начинать локальные формальные проверки как отдельную работу после
решения владельца; нельзя объявлять P6 завершённым или переносить на P7
непроверенные обещания научной достоверности.** В этом PR только рекомендации.

## Неизменяемое основание критериев

Действует `editorial-criteria.v1.json`, registry_version=1.0.0, IDs 01–34.
SHA-256 исходного Markdown:
`f13533887f2ce5c27291319b222d279880e5a496387096f309c02c7ee8eed66a`.
SHA-256 JSON:
`7fbe963ca146732ed4f91b0ba108c0610a384e508b3bcb82b796ee7d057b5be5`.
Реестр и исходник в аудите не изменены. Все 34 description отсутствуют в
источнике и явно представлены missing_in_source. Их нельзя заполнить

В roadmap есть конфликт названий: первоначальные P7a/P7b/P7c означают
«источники / служебный текст / повторы», а последующее дополнение использует
P7a для Editorial Review v2 и P7b для Corpus Linguistics. Ни одно из этих
направлений здесь не объявляется отменённым. Для следующих PR предлагаются
точные названия `formal-sources`, `formal-structure`, `formal-repetition`;
владелец должен согласовать нумерацию перед содержательным расширением.
Ниже P7a–c обозначают первоначальные формальные группы, не замену v2/corpus.

## Общие требования к началу

- Взять актуальную main, включающую рассмотренный финансовый fix #23, если
  выполняются P6-регрессии или используется его worker. Локальные правила не
  должны зависеть от ключа/согласия внешней модели.
- Добавлять ReviewRun/Finding отдельно от ModelJob Proposal. Записывать
  manuscript_revision_id, plan_revision_id при необходимости, registry version/hash,
  rule version/config hash, language/genre, входные признаки, coverage и статус.
  Миграция только добавляет сущности; не менять старые ManuscriptRevision/SourceVersion.
- Finding привязывается к block UUID + UTF-16 start/end + quote/hash + revision.
  Смена версии означает stale; автоматического переноса и правки текста нет.
  Ячейки, сноски, подписи — отдельные поддерживаемые текстовые узлы; покрытые
  merged cells не содержат скрытого текста. PNG pixels не анализируются.
- Использовать `candidate/no_issue/not_applicable/insufficient_data/error` и
  явное покрытие. Нет признака/не запускали правило — не no_issue. Диагностика
  структурной корректности P6 не становится выводом редакторского правила.
- Для каждого правила нужны позитивный сигнал, допустимое исключение, нехватка
  данных, RU/EN или честная языковая граница, UTF-16 emoji, конфликт версий,
  project isolation и неизменность старого DOCX. Малый целевой PR на группу правил.
- Выполнять все P2–P6 регрессии, миграции, frontend/build. При async job использовать
  существующую транзакционную дисциплину; не добавлять брокер без причины.
- Необходимые новые определения/пороги/жанры фиксировать в отдельной rule config,
  явно как проектные гипотезы. Менять смысл criteria v1 только по решению владельца
  новой версией реестра, не in-place.

## P7a / formal-sources — 09, 10, 11

Начать с чистых локальных функций DOI syntax/ISBN checksum/URL tracking
parameters поверх SourceVersion и Citation. Переиспользовать нормализацию P3;
ни checksum, ни DOI-синтаксис не подтверждают существование публикации.
Проверка DOI точным lookup и ранжированный текстовый поиск — разные результаты;
непопадание FAIR в top-5 не означает отсутствия источника.

Первый PR: Finding/coverage и офлайн-синтаксис/UTM-кандидаты. Следующий:
явно согласованные fixed-endpoint metadata checks, журнал времени/провайдера/
версии и статусов. 403/429/timeout/paywall → unavailable/error, не fabricated.
Не вводить произвольный URL fetch до отдельной SSRF-проверки DNS/redirect/private
IP/размера/таймаута. UTM removal — предложение diff с сохранением смысловых
параметров, не изменение исторической библиографии.

Приёмка: известный синтаксический дефект найден; корректный ISBN не объявлен
реальной книгой; сломанная сеть не обвиняет автора; точная SourceVersion остаётся
прикреплённой; без внешнего разрешения никакой автоматической сети.

## P7b / formal-structure — 12, 14, 21, 22, 23, 24, 25, 28, 30

Работать с типизированными P2 blocks/marks, а не с плоским текстом экспортного
DOCX. Начать с распознаваемых служебных фраз/плейсхолдеров/Markdown-артефактов
как candidate. Цитаты, интервью, письма в приложении, код, инструкции и реальные
официальные названия проверять как исключения. Регистр зависит от языка/жанра.

Критерий 24: явные marks в ручной рукописи доступны; отсутствие marks после
импорта не доказывает отсутствие жирного. Импорт теряет часть форматирования,
поэтому coverage должен отражать происхождение и insufficient_data. Не
восстанавливать несуществующую разметку догадкой. Ничего не удалять автоматически.

Приёмка: фрагмент открывается в точной версии, объяснение показывает правило
и проверенное исключение; обычные таблицы/merged cells/формулы/сноски/картинки
сохраняются; Finding не становится обязательным запретом экспорта без отдельной
согласованной политики.

## P7c / formal-repetition — 05, 16, 17, 26, 27, 29, 31, 32, 33

Начать с воспроизводимых метрик по языку/разделу: частоты и повторяемые
конструкции, длины предложений, позиции пунктуации. Сохранить tokenizer/splitter
version, размер окна и знаменатель нормировки. Формулы, библиографию, прямые
цитаты, списки и подписи считать раздельно; RU/EN профили не смешивать.

Сигнал — кандидат для автора, не нарушение из количества тире/троек/слов.
Без разрешённого размеченного корпуса пороги остаются экспериментальными,
а не нормативными. Не определять ИИ-авторство/плагиат по стилю. Группировать
пересекающиеся сигналы без удаления исходных ID 16/32, 26/29 и других.

Приёмка: метрика повторяется при тех же входах; допустимая классификация из
трёх пунктов и предметная терминология не помечаются автоматически ошибкой;
нет универсальной квоты и нет изменения смысла текста.

## Что не зависит от live P6 и что ждёт решения

Можно независимо подготовить схемы Findings/coverage, якоря, локальные
детерминированные правила, UI замечаний, исключения и регрессии DOCX.
Нельзя выдавать mock SemanticReview за научную проверку, использовать его
как gold labels для обучения или запускать платный review автоматически.

Editorial Review v2 требует согласованных descriptions/применимости/исключений;
Corpus Engine — лицензий и разрешённого набора, RU/EN профилей и разметки.
SQ01–SQ10 остаются отдельным namespace и будущим P8. Сначала нужно согласовать
слепую рецензию и смысловое coverage (A05 аудита); формальные Findings нельзя
сводить с SQ в единый процент «качества науки».

До регулярного использования реального P6 остаются live-протокол, экспертная
оценка, UI запуска отдельной рецензии, видимое происхождение принятого текста,
целевое backup/restore и Word-приёмка. Эти ограничения не блокируют разработку
локальных формальных правил и не считаются устранёнными началом P7.
