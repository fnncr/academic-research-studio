# P1a: персональные проекты и требования преподавателя

Первая поставка P1 добавляет PostgreSQL, миграции Alembic, создание/список/просмотр проектов и историю требований преподавателя. Проект содержит название, исследовательский вопрос и первую версию требований. Последующие требования добавляются отдельными версиями, старые доступны для чтения.

Это локальное приложение для одного владельца. Аутентификация и разграничение нескольких пользователей ещё не реализованы; API следует запускать только на loopback. Постоянное сохранение DOCX/PDF, удаление проектов, библиотека источников, редактор рукописи и полная система резервирования остаются последующими поставками. Отдельный раздел извлечения текста работает без БД и ничего не прикрепляет к проекту автоматически.

## Установка и запуск

Требуются Python 3.12+, Node 22.12+, Docker Compose v2 либо собственный PostgreSQL 17. Из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
# Пример локальной настройки: ввод без отображения, значение не сохраняется в Git.
read -rsp 'Пароль локального PostgreSQL: ' POSTGRES_PASSWORD
export POSTGRES_PASSWORD
printf '\n'
docker compose up -d --wait db
# SQLAlchemy URL строится с корректным экранированием специальных символов пароля.
export DATABASE_URL="$(.venv/bin/python - <<'PY'
import os
from sqlalchemy import URL
print(URL.create('postgresql+psycopg', username='studio', password=os.environ['POSTGRES_PASSWORD'], host='127.0.0.1', port=5432, database='studio').render_as_string(hide_password=False))
PY
)"
cd backend
../.venv/bin/alembic upgrade head
../.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Если используется собственная БД, установите `DATABASE_URL` с драйвером `postgresql+psycopg` через окружение и выполните миграции. URL не выводить в логи. Миграции запускаются явно, не при старте API. Без URL, при ошибочной настройке, недоступной БД или неприменённых миграциях маршруты проектов возвращают безопасный `503`, а health и извлечение документов остаются работоспособными. Учётная запись миграций должна иметь права создания таблиц, функции и триггера в выбранной схеме.

Во втором терминале из корня:

```bash
cd frontend
npm ci
npm run dev
```

Выберите «Проекты»: создайте проект, откройте сохранённый проект, добавьте требования новой версией, раскройте историю. После перезапуска API или обновления страницы сохранённые версии доступны из БД. Переключение между разделами в одной вкладке сохраняет текущий черновик; несохранённый текст не переживает обновление страницы. Перед открытием другого проекта сохраните свою редакцию требований.

Docker volume `studio_postgres` сохраняет БД после остановки контейнера. `docker compose down` сохраняет volume; `down -v` удаляет данные и не является штатной командой остановки. Пароль `POSTGRES_PASSWORD` применяется при первом создании volume; изменение переменной не меняет пароль уже существующей роли.

## Данные и API

Таблицы `projects` (UUID, название, вопрос, дата) и `brief_revisions` (UUID, project_id, номер, текст, дата). Номер положительный и уникален внутри проекта; внешний ключ не допускает версию без проекта. Проект и его первая версия создаются в одной транзакции. В БД установлен триггер, запрещающий UPDATE версии; API не предоставляет UPDATE/DELETE для истории. Права администратора БД не являются границей защиты приложения.

| Метод и путь | Результат |
| --- | --- |
| `POST /api/projects` | `201`, проект с `latest_brief`; JSON: title, research_question, requirements |
| `GET /api/projects?limit=20&offset=0` | Список проектов, новые первыми; limit 1–100 |
| `GET /api/projects/{uuid}` | Проект и актуальная версия требований |
| `GET /api/projects/{uuid}/brief-revisions?limit=20&offset=0` | История от новых к старым; limit 1–100 |
| `POST /api/projects/{uuid}/brief-revisions` | `201`, новая версия; JSON: base_revision_id, requirements |

Название — 1–200 символов, вопрос — 1–4000, требования — 1–20000; крайние пробелы убираются, пустые/пробельные значения, неожиданные поля и неправильные типы не принимаются. Даты включают часовой пояс. Тексты выводятся React как текст.

Запись новой версии блокирует строку проекта до завершения транзакции и сравнивает `base_revision_id` с актуальной версией. Из двух конкурентных запросов с одной базой только один сохраняется, другой получает `409 revision_conflict`. Черновик в UI сохраняется; действие «Загрузить актуальную версию, сохранив черновик» обновляет базу и показывает текущие требования для сравнения. Автор затем решает, отправлять ли свой текст новой версией. Блокировка не удерживается во время пользовательского редактирования.

При неизвестном UUID возвращается `404 project_not_found`, некорректных полях/UUID — стандартный FastAPI `422`, недоступности хранилища — `503 storage_unavailable`. Для прикладных ошибок `detail` содержит code/message/retryable. SQL, параметры подключения и текст требований не раскрываются в ответах. Старый контракт загрузки `/api/documents/extract` не меняется.

При неопределённом результате POST из-за обрыва соединения сначала обновите список/историю: автоматического повторения записи нет. Для массовых клиентов в дальнейшем потребуется идемпотентность создания. Эта поставка не меняет название и вопрос уже созданного проекта.

## Миграции и сохранность

`0001_projects` создаёт обе таблицы, FK, уникальность номера, индекс, функцию и триггер запрета UPDATE. Повтор `alembic upgrade head` безопасен. `alembic check` проверяет соответствие ORM и схемы. `alembic downgrade base` удаляет таблицы и все проекты: использовать только в одноразовой тестовой БД. Откат приложения не должен автоматически запускать downgrade.

Для персональной БД перед миграциями рекомендуется логический backup с правами доступа только владельцу:

```bash
umask 077
docker compose exec -T db pg_dump -U studio -d studio -Fc > studio-backup.dump
```

Восстанавливать сначала в отдельную новую БД, не поверх рабочей:

```bash
docker compose exec -T db createdb -U studio studio_restore
docker compose exec -T db pg_restore -U studio -d studio_restore --exit-on-error < studio-backup.dump
```

Проверить версии миграций, число проектов и историю требований до использования восстановленной БД. Политика автоматических backup, срок хранения и UI удаления остаются будущей частью P1. Файлы backup содержат пользовательские тексты: хранить вне Git в закрытом месте.

## Тесты

```bash
# Из корня; TEST_DATABASE_URL — отдельная PostgreSQL-БД с правом CREATE SCHEMA.
(cd backend && ../.venv/bin/python -m pytest -q)
(cd frontend && npm test && npm run build)
```

Интеграционные тесты читают `TEST_DATABASE_URL`, создают случайную собственную схему, выполняют реальные миграции и удаляют только эту схему в cleanup. Они не очищают рабочие таблицы. Без TEST_DATABASE_URL эти тесты явно пропускаются; в CI отсутствие настройки считается ошибкой. GitHub Actions запускает PostgreSQL service и весь набор. Trust-аутентификация используется только для одноразового CI-сервиса; локальный Compose требует пароль.

Проверяются транзакционный откат, конкурентные версии, неизменяемость истории, перезапуск приложения, пагинация, невалидные входы/ID, отсутствие миграций, upgrade/downgrade/upgrade и совпадение схемы с ORM. Старые тесты извлечения DOCX/PDF и реестра P0 сохраняются. Отдельные тесты проверяют, что реальное извлечение DOCX работает без БД/при неверном URL/при недоступном порте. Frontend-тесты покрывают создание, сохранение версии, конфликт с сохранением черновика и доступность загрузки при отказе проектов.

## Зависимости и решения

SQLAlchemy 2 — доступ к PostgreSQL (MIT); Alembic — явные миграции (MIT); psycopg 3 — драйвер (LGPL-3.0-only), пакет psycopg-binary содержит также лицензии встроенных библиотек. Метаданные лицензий проверены при добавлении; версии зафиксированы в requirements.txt. PostgreSQL — PostgreSQL License. Использование синхронных SQLAlchemy-сессий в обычных `def` маршрутах FastAPI переносит блокирующий I/O в thread pool; существующий async upload остаётся отдельным. Соединения ограничены пулом, connect/statement/lock timeout; пул освобождается при остановке приложения. Создание engine не выполняет сетевое подключение на старте.
