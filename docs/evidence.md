# P4a: серверная основа доказательств и плана

Первая поставка P4 добавляет ручной API без внешних вызовов и новых зависимостей. Интерфейс работы с доказательствами, перенос привязок между версиями рукописи, переводы и научная проверка остаются следующими поставками. P3 не считается полностью проверенным; результат его отдельной live-проверки описан в [sources.md](sources.md).

Из `backend` выполните `../.venv/bin/alembic upgrade head` (`0004_evidence_plan`). Используйте локальный API `/docs` для просмотра и отправки запросов. Сначала создайте проект, сохраните источник и рукопись через существующий интерфейс.

## Доказательство

`POST /api/projects/{project_id}/evidence` принимает `request_id`, точный `source_version_id`, `excerpt`, `selection: {start,end,quote}`, `locator: {kind,label}`, `material`, `note`, `rights_confirmed: true`. `material` — `abstract` или `full_text_excerpt`; локатор — `page`, `section` или `paragraph`. Фрагмент и цитата — до 12000 символов, заметка до 2000, локатор до 500. Пользователь подтверждает право сохранить предоставленный материал. Тексты сохраняются в PostgreSQL по этому явному запросу; сторонним сервисам не передаются.

Диапазон полуоткрытый в единицах UTF-16, как JavaScript selectionStart/selectionEnd. Сервер проверяет точное совпадение цитаты с фрагментом и отклоняет границу внутри surrogate pair. Например, для `А🧪Б` диапазон `[1,3)` выделяет `🧪`. Локатор фиксируется со слов пользователя и остаётся непроверенным: совпадение с введённым фрагментом не доказывает точности оригинала или прочтения всей статьи.

`GET /evidence?limit=20&offset=0` возвращает список (максимум 100). `GET /evidence/{id}` возвращает также точную старую версию метаданных источника. Ответ всегда содержит `verification: user_supplied_excerpt`, `locator_verification: unverified`, `full_text_verified: false`, включая фрагменты полного текста. Исправление создаёт новый Evidence с новым ID; старые данные остаются доступны планам. UPDATE/DELETE запрещены триггером.

## Версии плана, тезисы и ссылки

`GET /research-plan` возвращает последний план либо null. `POST /research-plan/revisions` принимает:

```json
{
  "request_id": "UUID",
  "base_revision_id": null,
  "manuscript_revision_id": "UUID сохранённой версии рукописи",
  "document": {
    "schema_version": "1",
    "claims": [{
      "id": "стабильный UUID тезиса",
      "statement": "Формулировка тезиса",
      "section_id": null,
      "evidence": [{"evidence_id": "UUID", "relation": "contradicts", "rationale": "Объяснение автора"}]
    }],
    "citations": []
  }
}
```

`section_id` может указывать только на заголовок выбранной версии рукописи. Relation: `supports`, `contradicts`, `limits`. Тезис без доказательств разрешён как исследовательский пробел, без статуса подтверждения. Поддержка или противоречие — решение автора; система его научно не проверяет. Русские и иностранные позиции можно связывать с одним тезисом, сохраняя оригинальные цитаты и отдельные объяснения.

Citation содержит `id`, `claim_id`, `evidence_id`, `block_id`, `selection: {start,end,quote}`, `kind: quotation|paraphrase`. Evidence должен быть связан с этим тезисом. Диапазон проверяется в точной сохранённой версии рукописи, в том числе внутри пункта списка или ячейки таблицы. Для `quotation` текст также должен точно совпасть с цитатой Evidence; для `paraphrase` смысловое соответствие оценивает автор. Автоматической подстановки библиографии и экспорта пока нет.

`GET /research-plan/revisions?limit=20&before=номер` возвращает историю; `/research-plan/revisions/{id}` — снимок. До 100 тезисов, 30 свидетельств на тезис, 200 citations. Все записи и ссылки проверяются на принадлежность проекту. Тело запроса ограничено 256 КиБ, время чтения — 15 секунд; ошибки не отражают приватные тексты.

## Хранение и конфликты

Выбран атомарный снимок Claim/Citation в ResearchPlanRevision: один POST сохраняет согласованную карту целиком и привязывает её к неизменяемой ManuscriptRevision. Это соответствует существующему редактору P2 и позволяет избежать частично сохранённых связей. Evidence хранится отдельно с FK на SourceVersion; таблица PlanEvidenceReference с реальными FK закрепляет все используемые доказательства. История и таблица связей защищены от UPDATE/DELETE триггерами. Удаление используемого источника не допускается FK; API удаления пока отсутствует.

`base_revision_id` — ID последнего плана (null только для первого). Две вкладки получают 201/409; строки проекта блокируются на время транзакции. Повтор того же `request_id` и тела возвращает исходный результат даже после следующей версии. Повтор ключа с другим телом даёт 409. При исправлении сохраняйте стабильные ID тезисов и создавайте новую версию плана. Новая рукопись не меняет старые привязки автоматически; для новой версии плана требуется явно выбрать revision и заново проверить диапазоны.

Проверка: `TEST_DATABASE_URL=… ../.venv/bin/python -m pytest -q tests/test_evidence.py`. Нужна отдельная тестовая PostgreSQL-БД. Тесты используют синтетические материалы, реальные миграции, конкурентные запросы и отдельные схемы. Проверяются перезапуск, права проекта, UTF-16, конфликты, неизменяемость, FK, downgrade/upgrade и сохранность P2/P3.

## P4b: пользовательский интерфейс

В проекте откройте рукопись P2, сохраните её и нажмите «Открыть научные доказательства». Библиотеку P3 можно открыть рядом. Работа с Evidence/Claim/Citation использует API P4a и не вызывает каталоги или модели. Для начала нужен хотя бы один источник в библиотеке и сохранённая рукопись.

1. Выберите публикацию и конкретную версию; при необходимости загрузите более старые версии. Вставьте оригинальный фрагмент, выделите точную цитату мышью или клавиатурой. Задайте язык оригинала (`ru`, `en`, `und` и другие коды), тип и значение локатора, вид материала и подтвердите право сохранения. Страницы и цитаты не заполняются автоматически.
2. Сохраните доказательство. Библиотека показывает оригинальный фрагмент, точную версию метаданных, локатор и статусы. Обновление и постраничная загрузка доступны отдельно. Исправление фрагмента сохраняется новым Evidence; старый остаётся в истории.
3. Создайте тезис, выберите заголовок сохранённой рукописи. Добавьте русскоязычные и иностранные Evidence, для каждого выберите «Подтверждает», «Противоречит» или «Ограничивает применимость», укажите объяснение. Все связанные версии публикаций доступны прямо в тезисе. Связь не означает научного подтверждения.
4. В области цитирования выберите тезис и связанный Evidence, затем блок, пункт списка или ячейку сохранённой рукописи P2. Выделите диапазон в текстовом поле и выберите прямую цитату или пересказ. Прямая цитата обязана точно совпадать с сохранённой цитатой источника. Добавьте связь и сохраните версию научного плана.
5. После перезагрузки откройте ту же область: сохранённые тезисы и citations восстановятся. История позволяет просмотреть старый план и загрузить его в черновик. Следующее сохранение добавит новую версию с теми же UUID тезисов и citations; прежние версии остаются неизменными.

Несохранённая рукопись блокирует изменение плана/цитат. После сохранения новой рукописи показывается конфликт привязки: пользователь явно подтверждает переход, старые ranges черновика удаляются и разделы сбрасываются для повторного выбора. Они остаются в сохранённой истории. При изменении рукописи в другой вкладке проверка перед сохранением блокирует запись и предлагает загрузить актуальный текст через P2. Автоматический перенос диапазонов не выполняется.

Конфликт плана 409 сохраняет черновик, показывает актуальные данные рядом с ним и требует подтверждения сравнения перед новой записью. Потеря ответа допускает повтор с тем же request UUID. Форма сохраняется в памяти вкладки; переключение проекта и закрытие страницы предупреждают о несохранённых данных. Постоянного локального черновика нет.

Минимальное расширение P4a: поле `original_language` хранится внутри JSON содержимого Evidence; миграция не требуется, старые записи отображаются с `und`. Это язык фрагмента, отдельно от языка библиографической карточки. Оригинальный текст не заменяется переводом. Совместимость request hash для прежних запросов без языка сохранена. Модель Claim/Citation, таблицы и неизменяемые версии не переписаны. Поля точной версии, оригинальной цитаты, отношения и авторского объяснения остаются доступными будущим Corpus Engine и SQ01–SQ10; сами эти модули пока не запускаются.

Проверки P4b: компонентные frontend-тесты проходят сценарий источник → Evidence → тезис → citation → сохранение → повторное открытие → восстановление новой версией, потерю ответа, конфликт, смену рукописи и языки. Они используют API-имитацию. Отдельный интеграционный backend-тест повторяет сохранение/перезапуск/восстановление на настоящей PostgreSQL. Это не тест браузера с реальной БД. Дополнительный ручной просмотр и содержательная приёмка автора остаются необходимыми.
