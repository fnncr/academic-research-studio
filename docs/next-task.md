# Продолжение после первой поставки P3

Репозиторий `fnncr/academic-research-studio`. P0, P1a и P2 объединены в main (`6053388`, PR #3–#5). Первая поставка P3 публикуется веткой `feat/p3-source-library`. Проверь фактический PR, CI и main; не полагайся на локальные файлы предыдущего облачного окружения и не разрабатывай готовые блоки заново.

## Готовое задание следующей задаче

Прочитай AGENTS.md, docs/architecture.md, docs/roadmap.md, docs/sources.md, docs/research-quality.md, docs/manuscripts.md, критерии 01–34 и JSON-реестр. Работай небольшими PR, сохраняя тесты и ручной режим без ключей. Не изменяй main напрямую и не объединяй без успешного CI и явного разрешения владельца.

Сначала заверши эксплуатационную приёмку P3. В предыдущем окружении оба внешних API возвращали ProxyError: api.crossref.org и api.openalex.org не разрешены сетевой политикой. В настройках среды разрешить HTTPS к этим доменам; при необходимости настроить OPENALEX_API_KEY как секрет. Не обходить proxy и не редактировать локальную policy для получения доступа. Проверь текущие официальные API/квоты/лицензии/ключи, выполни по одному небольшому реальному поиску без пользовательских документов и зафиксируй фактический результат. Архивная документация не подтверждает сегодняшние условия.

Следующий законченный блок P3: решения включения/исключения источников с причиной, поиск по сохранённой библиотеке, обоснованная интеграция ISBN-каталога. Если добавляешь произвольные URL, нужен отдельный дизайн SSRF/DNS-rebinding/TLS/редиректов; одной DNS-проверки перед GET недостаточно. Сейчас URL не запрашиваются. 403/таймаут/пустая выдача — непроверенность, не вымысел. Секреты и пользовательские документы не должны попадать в логи.

Затем P4: Evidence/Claim/Citation на неизменяемых SourceVersion/ManuscriptRevision, точные цитаты/локаторы, поддерживающие и противоречащие свидетельства, сопоставление русских и иностранных подходов. Метаданные не означают прочитанный полный текст. Разрешённый перевод сохраняет оригинал, терминологию, авторство и ссылку; не заменяет самостоятельное исследование.

Corpus Linguistics и Scientific Quality Review SQ01–SQ10 описаны в docs/research-quality.md как будущие модули. BAWE/MICUSP и русскоязычный корпус не загружать до подтверждения конкретных условий: чтение, массовая загрузка, локальный анализ, распространение и обучение — отдельные права. Профили разделять по языку/жанру/дисциплине; готовые предложения не копировать. Не запускать дорогое дообучение без обоснования и разрешения.

Editorial Review v2 готовить в P7/P8: сохранить ID/смысл 01–34, предложить descriptions, применимость, исключения, пересечения и тесты для отдельной приёмки. Не переписывать действующий реестр 1.0.0. SQ-проверки вводить постепенно с фрагментом, основанием, статусом достоверности и insufficient_data при нехватке материала. Наличие спецификации не означает реализованную проверку.

P5 требует конкретного образца Финансового университета/преподавателя: произвольный шаблон не является официальным. Для P6 нужны модель, бюджет и разрешение внешней передачи. Перед финальным DOCX нужны отдельные Source Validator, Critical Reviewer, Editorial Reviewer, Citation Auditor и Document Validator. Сохраняй открытые ограничения P1: assets, удаление проектов, автоматические backup.

Для каждого готового блока: код, тесты, документация, опубликованная ветка/PR, фактические результаты и ограничения. При блокировке доступа укажи точное требуемое действие и продолжай доступные независимые работы.
