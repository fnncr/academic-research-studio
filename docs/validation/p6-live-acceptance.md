## Один воспроизводимый синтетический случай

Использовать отдельный проект без личных/учебных рукописей. Данные ниже
вымышлены специально для теста, не являются результатами опубликованных работ.
Создать записи через обычные P1–P4 API; сохранить ответы с реальными назначенными
UUID. Не присваивать фиктивный DOI/ISBN и не обозначать источник verified.

Research Question: «Позволяют ли эти синтетические наблюдения заключить,
что учебная программа вызывает улучшение результата?»

Требования: «Сопоставить позиции A/B/C, отделить ассоциацию от причинности,
сохранить цитаты на оригинальном языке, указать недостаток данных.
Не вводить новые публикации, авторов или численные результаты».

Сохранённый раздел: заголовок «Синтетический анализ», абзац «Проверяются
только предоставленные тестовые материалы». Claim: «Учебная программа
может быть связана с улучшением результата; причинность ещё не установлена».

| Тестовая SourceVersion | Язык / relation | Полный оригинальный фрагмент = точная selection | Локатор |
| --- | --- | --- | --- |
| SYNTHETIC A — observational fixture | ru / supports | В синтетической группе участников программы результат выше. Распределение в группы не было случайным. | section: fixture A |
| SYNTHETIC B — contradictory fixture | en / contradicts | In this synthetic sample, the adjusted association was not distinguishable from zero. This is not proof of no effect. | section: fixture B |
| SYNTHETIC C — limitations fixture | en / limits | This synthetic example has a small convenience sample and no randomized assignment. Causal and population-wide conclusions are unsupported. | section: fixture C |

В metadata: только указанный title, kind=report, language; authors=[], year=null,
doi/isbn/url=null. Отсутствующие выходные данные должны остаться диагностикой,
а не автоматически дополниться. original_language хранить в Evidence отдельно.
rights_confirmed допустим для этих специально созданных синтетических строк.
Диапазоны selection вычислить в UTF-16; сохранить полные ответы API и хеши.

## Условия разрешения

Перед отправкой владелец отдельно подтверждает:

1. OpenAI, точный snapshot gpt-4.1-mini-2025-04-14, его доступность аккаунту и

   Замена модели требует нового контракта/тарифа, не alias fallback.
2. Передачу только указанного синтетического контекста; текущие условия региона,
   хранения/кеша/обучения. store=false не является обещанием ZDR.
3. Тариф input/cached/output и верхнюю границу; отдельный ключ приложения
   ARS_OPENAI_API_KEY. Никогда не ключ ChatGPT/Codex и не ключ в браузере/отчёте.
4. **Один writing вызов**, max_output_tokens=2000; отдельно решает, разрешать ли
   **один SemanticReview** с новым UUID/consent и тем же output cap.
5. Project budget **421431 micro-USD** для writing либо **842862 micro-USD**
   для writing + review. Per-call ceiling **421431 micro-USD** при неизменном
   проверенном тарифе. Это $0.421431 / $0.842862 модельного usage, не обещание
   окончательного счёта с налогами. Изменённая котировка требует нового согласия.

Флаги ARS_OPENAI_APPROVAL / ARS_OPENAI_PRICE_CONFIRMED должны соответствовать
POLICY в проверенном коде; сетевой доступ и доверенный TLS настраиваются штатно.
Настройка сама по себе не является согласием на конкретный task fingerprint.

## Методика оценки качества будущего ответа

Зафиксировать fixture/version, модель, prompt/schema, параметры и результат.
Два человека независимо размечают фрагменты; один может быть владельцем,
другой — предметным экспертом. Если второго нет, указать single-reviewer limit.
Разногласия сохраняются, а не скрываются общим баллом. Не отправлять экспертные
данные внешнему сервису без отдельного согласия.

Для каждого измерения использовать `adequate / concern / insufficient_data /
not_applicable`, с точным фрагментом, Evidence/SourceVersion и объяснением:

| Измерение | Проверяемое основание | Будущая связь SQ |
| --- | --- | --- |
| Доказательная обеспеченность | Каждое проверяемое утверждение сопоставлено с достаточным Evidence, отсутствие данных названо | SQ01, SQ05 |
| Точность ссылок | Допустимая версия, точный локатор, совпадение цитат; нет неподтверждённой атрибуции | SQ02 |
| Учёт противоречий | B действительно обсуждается, а не только числится в JSON; ограничения C не исчезли | SQ06, SQ10 |
| Терминология | Association/effect/causation различаются, RU/EN смысл не заменён | SQ07 |
| Логика | Нет перехода от корреляции к причинности и от отсутствия значимости к отсутствию эффекта | SQ03, SQ04 |
| Отсутствие вымышленных источников | Нет новых авторов/DOI/результатов даже в свободном prose | SQ02, SQ05 |
| Смысл цитат | Оригинал сохранён, контекст/отрицание/условия не потеряны | SQ02, SQ10 |
| Академический стиль | Осторожные, ясные формулировки без заявленной проверки истины | Редакторские 01–34, не отдельный балл SQ |
| Структура раздела | Вопрос → сопоставление → ограниченный вывод → пробел; не коллаж выдержек | SQ01, SQ09 |
| Полезность исследователю | Понятно, какие данные нужны дальше и что остаётся ручной проверкой | SQ08, SQ09 |

Не усреднять эти значения в «процент научной достоверности». Один придуманный
источник/искажённая цитата означает неприемлемый результат до исправления и
повторной человеческой проверки, даже если остальные размеры adequate.
Synthetic live case проверяет интеграцию, не качество модели на реальной науке.
Для регулярного применения потребуется отдельно согласованный набор реальных
материалов с правами использования, жанрами/дисциплинами/языками и отложенной
экспертной выборкой. Это будущая приёмка, не реализованный P8.
