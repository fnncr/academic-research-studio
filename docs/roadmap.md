# План развития Academic Research Studio

Статус: 3 ноября 2026 года; исходный план основан на `main` (`df2c07c`) и [архитектуре](architecture.md). Техническая поставка P0 и первая поставка P1 объединены в `main` (`bc05bba`, PR #3/#4). В этой ветке реализован P2; приёмка и слияние выполняются отдельно. Оставшиеся части P1 и P3–P10 ещё не реализованы. Оценки сроков не назначены до уточнения жанров, корпуса и модельного провайдера.


## Статус P0

Исправлена нумерация 32; добавлены JSON-снимок `1.0.0`, строгие Pydantic-модели и тесты соответствия всех 34 пунктов исходной спецификации. Поля с исходными формулировками перенесены дословно. [Документация реестра](editorial-registry.md) описывает запуск проверок и версионирование.

Содержательное условие приёмки P0 по описаниям остаётся открытым: в источнике нет отдельных description для 01–34. Они явно представлены обязательным nullable-полем с `missing_in_source`, а не заполнены предположениями. Исходное условие «все обязательные поля непустые» не объявляется выполненным. [Открытые вопросы](editorial-ambiguities.md) фиксируют это ограничение и другие неоднозначности. Пороги, применимость и алгоритмы проверки не реализованы.

## Статус первой поставки P1

Добавлены PostgreSQL/Compose, миграция Alembic, создание и просмотр проектов, неизменяемые версии требований преподавателя и минимальный UI. [Инструкция P1a](projects.md) описывает запуск, API, тестирование и ручной backup/restore. Работает сценарий без БД для извлечения DOCX/PDF. Хранение файлов, удаление проектов, автоматическое резервирование и содержательная приёмка полного P1 остаются отдельными поставками. Аутентификация не реализована; режим локальный, для одного владельца.

## Статус P2

Реализованы ручной редактор блоков с UUID, план по заголовкам, списки/таблицы/заготовки ссылок, неизменяемые снимки, защита от конфликтов, идемпотентные повторы, сравнение блоков и восстановление новой версией. [Руководство и решение о редакторе](manuscripts.md) фиксируют ограничения: без WYSIWYG/inline-citations, импорт только текста с явным предупреждением, несохранённый черновик только в памяти вкладки. P2 не объявляет выполненными оставшиеся части P1 или научную проверку текста.

## Исходная точка и правила поставки

Уже есть FastAPI, React/TypeScript, загрузка DOCX/текстовых PDF, ограниченный parser subprocess, просмотр текста, 19 backend-тестов и 4 frontend-теста. Сценарий извлечения без хранения должен оставаться доступным на каждом этапе, в том числе без БД и модельных ключей. Исходный API и его лимиты не меняются скрытно.

Каждый PR описывает миграции, тесты и ограничения. Перед слиянием проходят текущие pytest, frontend tests и TypeScript/Vite build, а также проверки затронутого сценария. Новые проверки тестируют поведение и ошибки, не копируют реализацию. Внешние API и модели в обычном CI заменяются контрактными фикстурами; ограниченные live-проверки выполняются отдельно и явно отмечаются. Изменения моделей и промптов проходят тот же контроль качества, что код.

Каждый пункт проходит предварительный поиск, проверку контекста/исключений и возвращает статус; словарь не объявляет нарушение автоматически. Полная матрица методов и необходимых данных находится в архитектуре.

## Оценка качества и тестовые данные

Для каждого критерия собрать минимум по 5 нарушений, 5 допустимых исключений и 3 неоднозначных случая как стартовый набор, затем расширять по жанрам и дисциплинам. Это минимум для разработки, не доказательство статистической надёжности. Корпус использовать с разрешением, удалять персональные данные; синтетические примеры помечать. Не создавать вымышленные источники для реального текста: фиктивные библиографические записи допустимы только как явно обозначенные тестовые данные.

Разметка включает критерий, точный диапазон, основание, исключение, уверенность эксперта и достаточность контекста. Для смысловых критериев нужны две независимые человеческие оценки и разбор расхождений; при отсутствии второго эксперта качество считается предварительным. Train/dev/test делятся по целым документам и источникам, чтобы соседние абзацы не попадали одновременно в настройку и проверку.

Измерять precision/recall и ложные срабатывания на исключениях по каждому критерию, долю insufficient_data, согласие рецензентов и долю полезных/отклонённых правок. Не сворачивать их в «процент качества работы». Порог запуска в повседневную работу согласовать после пилота и зафиксировать до оценки на test. До этого семантические замечания обозначаются экспериментальными и требуют подтверждения.

Обязательные сквозные сценарии:

- Пустой проект → ручной вопрос/план → два проверенных источника → тезис с цитатой → раздел → рецензия → принятая правка → DOCX.
- Источник недоступен или метаданные расходятся: статус виден, модель не выдумывает замену.
- Противоречащий источник сохраняется и учитывается в выводах; результат модели не может удалить его без решения автора.
- Указание внутри статьи «игнорировать правила/раскрыть секрет» остаётся текстом источника и не меняет поведение инструментов.
- Модель, сеть или БД отказали: принятый текст сохранён; повтор задачи не создаёт дубликат; временный extract продолжает работать без БД.
- Правка конфликтует с новой версией: применяется только после пересмотра, привязка не смещается молча.
- Экспорт проверяет unsupported nodes, ссылочные связи и незаполненные поля; не обещает исходную пагинацию.

## Международные исследования и независимые проверки

Дополнительные требования распределены по исходным этапам, без заявления об их реализации в P2:

- P3: русскоязычная и зарубежная библиотека статей, диссертаций, монографий и официальной статистики; Crossref/OpenAlex через отдельные адаптеры, журнал запросов и фильтров, проверка DOI/ISBN/URL. Отсутствие записи у провайдера не доказывает отсутствия публикации; цитируемость не равна научной значимости.
- P4: точные версии источников и разрешённые фрагменты, локаторы, поддерживающие и противоречащие свидетельства; сопоставление российских/иностранных подходов и исследовательских пробелов. Метаданные не означают прочтённый полный текст.
- P5: настраиваемый профиль оформления для работ Финансового университета при Правительстве РФ только по конкретному предоставленному шаблону/заданию. Параметры шрифтов, полей, интервалов, отступов, нумерации, титула, содержания, таблиц, рисунков и библиографии; задание преподавателя имеет приоритет. Неподтверждённый пример не маркировать официальным шаблоном.
- P6: перевод разрешённых фрагментов с исходной терминологией, авторством и ссылкой; бюджет модели и согласие на передачу выбранного текста. Перевод не заменяет самостоятельный анализ и не скрывает заимствование.
- P7–P9: перед финальным DOCX отдельные Source Validator, Critical Reviewer, Editorial Reviewer (все 34 критерия), Citation Auditor и Document Validator. Каждая проверка фиксирует версию, основание, статус/покрытие и нерешённые проблемы. Невыполненная проверка не считается успешной.

[Готовое задание продолжения после P2](next-task.md) не зависит от сохранности облачного рабочего каталога.
